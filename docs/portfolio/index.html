01 / The engineering problem

Correctness when
requests go wrong.

A payment request can arrive twice. Two transfers can compete for the same balance. A correction must preserve the original record.

This project models those failure cases around an append-only, double-entry ledger. The entry stream records each movement; balance snapshots provide fast reads and change within the same database transaction.

01

Retries return the original result

Persisted idempotency keys, normalized request fingerprints, and initiator checks reject conflicting reuse.

02

Spending follows the lock

Account rows are locked in stable order. The available balance is checked after locking, before posting.

03

Corrections add evidence

Reversals append opposite entries and link to the original transaction. PostgreSQL triggers reject mutation of posted records.

04

Currencies balance independently

Integer minor units represent money. Fixed-precision FX quotes include a fee, an expiry, and one-time consumption.

03 / Implementation scope

From ledger rules
to a usable system.

Payments

Wallets, deposits, transfers, FX and reversals

Running statements and signed transaction entries make each operation inspectable.

Reliability

Signed events and settlement reconciliation

Provider event IDs and payload hashes detect duplicate delivery. Settlement exceptions are retained for investigation.

Access

Subject ownership and administrator controls

Wallet, quote and initiated-transaction access is checked against the caller. The bundled identity directory uses configurable Basic authentication.

Delivery

One-command setup and multi-architecture images

Docker Compose starts the console, API and PostgreSQL. A demo workspace seeds two wallets and a GBP 100.00 deposit.

Latest main

Trace-linked operational telemetry

Optional OpenTelemetry export connects HTTP and worker signals with request traces and Prometheus exemplars. Added after the v0.3.0 release.

05 / Run the project

Clone. Start. Inspect.

With Docker and Compose v2 installed, start the full stack locally. Open localhost:8080 and select Create demo workspace.

Then transfer funds, execute an FX quote, reverse a transaction, and inspect the statement and invariant check.

Engineering judgment

The next production steps are explicit.

This is a runnable engineering reference with a provider simulator. Independent public users would need external identity, regulated payment controls, a durable outbox relay, coordinated multi-worker processing, and measured load and recovery testing.
